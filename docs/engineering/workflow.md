# 开发工作流

从根 AGENTS、manifest/services、当前进度和已确认材料继续。新建/恢复或新增能力由用户级 ai-coding-project 处理；业务实现直接按本项目规则推进，不依赖独立开发技能。

本轮目标 → 已确认需求/原型 → 助手维护 Spec → 有序实现 → 相关检查 → 本人试用 → 记录结果和下一步。需求已明确不重复询问；中大型改动说明复用、改动、顺序、失败恢复和验收，小修复沿当前记录。

本地功能读取 local.md；阶段记录与失败恢复读取 efficient-execution.md；项目运行和依赖恢复读取 project-execution.md。发布、云端/AI、Android 按当前需求读取对应用户级技能指南。新增能力时用 Enable-ProjectCapability 登记当前项目绑定，同一任务继续实际接入；不安装项目平台技能副本。

异步表单的接口/调用方、首个编译错误和浏览器操作/证据读取 [Web 实现与验收](web-verification.md)。这些方法按本轮改动使用，不因增加通用指引就重复已有验收或改变产品范围。

缺运行环境时恢复原引擎/镜像；缺依赖在同镜像原卷恢复；授权失败仅修当前平台绑定；发布不明先查真实状态；APK旧内容沿 Web→sync→包资源排查。技术修复不交给本人试错，不改变已确认架构、资源或权限绕过失败。

本地初始化、所选能力接入、真实功能、发布及本人试用分开记录。本地检查通过不代表所请求的云端任务已经完成；未选择的能力不生成待办。当前凭证与目标只从明确项目绑定发现，不扫描秘密。
